# 11. アプリの通行証 — 部屋のメンバーなら、アプリの前のベーシック認証を飛ばす

2026-10-18 起こす。issue は #607。相手側 (hikousen-rs.com の入口) は portal班が作る。

## 1. なぜ作るか

部屋のアプリパネル (`rooms.app_urls`) は、登録した URL を iframe でそのまま開くだけで、Tealus は中身に関わらない。
登録されているアプリのうち 5 件 (`hikousen-rs.com/close/…`) は、Apache のベーシック認証の内側にある。

★ **iPhone の利用者が、アプリを開くたびにパスワードを打たされている** (現場の負担が大きい。2026-10-18 小野さん)。

★ Tealus にログインできて、その部屋のメンバーであるなら、スタッフ専用ページを開いてよい人である
(通す範囲は**その部屋のメンバー**。Tealus にいるだけの人 (ベータテストの方・AI 班・機械) は通さない)。

## 2. 何を作るか (一言で)

Tealus は、アプリを開くときに、**2 分だけ有効な署名つきの通行証**を作り、相手側の**入口** (`/tealus-gate/`、守られていない場所) へ送る。
入口 (PHP) がそれを確かめ、**12 時間有効なクッキー**を渡して、通行証に書いてあるアプリのページへ移り直す。
以後は、そのクッキーがあればベーシック認証の代わりに通す。

★ 入口を `/close/` の**外**に置くのは、Apache が `.htaccess` の認証を URL の書き換えより先に済ませるため。
`/close/…?tealus_pass=…` を直接開くと、まだクッキーが無いので、入口の PHP に届く前に断られる。

```
利用者 (iPhone の Tealus)
  │ アプリを開く
  ▼
Tealus サーバ  POST /api/rooms/:id/app-pass
  │ ・その部屋のメンバーか
  │ ・そのアプリに「通行証を添える」が付いているか
  │ ・宛先のサイトの鍵があるか
  │ → 通行証 (行き先のページ to を含む) を署名する
  ▼
iframe が  https://hikousen-rs.com/tealus-gate/?tealus_pass=v1.xxx.yyy  を開く
  ▼
相手側の入口 (PHP、/close/ の外)
  │ 署名 → 宛先 → 期限 の順に確かめる
  │ → クッキー tealus_gate (Partitioned、12 時間) を渡す
  │ → 通行証の to (例 /close/qrpos/?pmode=tana) へ移り直す
  ▼
/close/ の .htaccess   パネルの中: 有効な tealus_gate だけ / それ以外: ベーシック認証 または 有効な tealus_gate
```

★ ベーシック認証は**残す**。ふつうのブラウザで直接開く人には、これまでどおり出る。

## 4. 通行証の決まり (相手側はこの節だけ読めば作れる)

### 4.1 形

```
tealus_pass = "v1." + base64url(中身の JSON) + "." + base64url(HMAC-SHA256(鍵, "v1." + base64url(中身の JSON)))
```

- base64url は `+` → `-`、`/` → `_`、末尾の `=` を取る (RFC 4648 §5)
- 署名の対象は、**送られてきた文字列そのまま** (`v1.` + 中身の部分)。JSON を組み直してから署名を計算しないこと

### 4.2 中身 (JSON)

| 名前 | 型 | 意味 |
|---|---|---|
| `v` | 数 | 1 |
| `aud` | 文字列 | 宛先のサイトの origin (例 `https://hikousen-rs.com`)。★ 自分の origin と一致しなければ落とす |
| `room` | 文字列 | Tealus の部屋の ID (UUID)。★ ホーム画面のタブから出したときは `"home"` (§5.4)。相手側は形を決め打ちしないこと |
| `sub` | 文字列 | Tealus の利用者 ID (UUID)。監査用 |
| `name` | 文字列 | Tealus の表示名。記入者の欄に使ってよい (★ 長さの上限は相手側で切り詰める) |
| `to` | 文字列 | 行き先のページ。アプリの URL の**パスと問い合わせ** (例 `/close/qrpos/?pmode=tana`)。必ず `/` で始まり、`//` では始まらない |
| `iat` | 数 | 出した時刻 (Unix 秒) |
| `exp` | 数 | 期限 (Unix 秒) = `iat + 120` |

### 4.3 確かめる順番 (入口の PHP)

1. 形: `v1.` で始まり、ピリオドで 3 つに分かれる。でなければ落とす
2. **署名**: 自分の鍵で計算し、`hash_equals` で比べる (時間差で漏らさない)。違えば落とす
3. 中身の JSON を読む。読めなければ落とす
4. `v === 1`、`aud` が自分の origin と一致。でなければ落とす
5. **期限**: `exp >= time()`。過ぎていれば落とす。★ 時計のずれは 30 秒まで見逃してよい (`exp + 30 >= time()`)
6. `to` が `/` で始まり、`//` でも `/\` でも始まらないこと。でなければ落とす (よそのサイトへ飛ばされないため)
7. 通ったら、クッキー `tealus_gate` を渡し、`to` へ移り直す (`Location: <自分の origin><to>`)

★ 2 より前に中身を信じないこと (署名を確かめる前の `name` や `to` は誰でも書ける)。
★ 落としたときは「アプリを開き直してください」の案内を出す (入口は守られていない場所なので、ベーシック認証には流れない)。
★ アプリの URL のハッシュ (`#…`) は、Tealus が入口の URL の末尾に付ける。移り直しの `Location` にハッシュが無ければ、ブラウザが引き継ぐ。

### 4.4 クッキー `tealus_gate` (相手側の持ち物。Tealus は関わらない)

- 値 = `期限.署名`。期限 = **JST** の `yyyymmddhhmmss` (14 桁、`%{TIME}` と同じ基準)、署名 = `sha1(クッキー用の合言葉 . 期限)`
- 期限 = 通行証を確かめた時刻 + **12 時間**。★ **延長しない** (§6.1)
- 属性: `Path=/; Secure; HttpOnly; SameSite=None; Partitioned`
- `.htaccess` (頭と尾を固定すること。部分一致だと別名のクッキーに仕込んで通れる):

```apache
Require expr "%{HTTP_COOKIE} =~ /(?:^|;\s*)tealus_gate=([0-9]{14})\.([0-9a-f]{40})(?:;|$)/ && $2 == sha1('クッキー用の合言葉' . $1) && $1 -gt %{TIME}"
```

- ★ 二重引用符の中の補間 (`sha1("合言葉$1")`) は 500 になる。`.` で繋ぐ形を使う (portal班の実測)
- 名前 (`name`) を後のページで使うなら、別のクッキーに入れる (相手側の作り)
- ★ **パネルの中ではパスワードの入力欄を出さない** (portal班の実測、2026-10-18 15:05)。期限切れの要求に 401 を返すと、パネルの中に入力欄が出る。
  `Sec-Fetch-Dest: iframe` の要求だけはベーシック認証を外し、クッキーが無ければ 403 + 案内のページ (`/tealus-gate/` の中、守られていない場所) にする

```apache
ErrorDocument 403 /tealus-gate/expired.html
<If "%{HTTP:Sec-Fetch-Dest} == 'iframe'">
    Require expr "<上の tealus_gate の式>"
</If>
<Else>
    AuthType Basic
    # (AuthName / AuthUserFile は今のまま)
    <RequireAny>
        Require valid-user
        Require expr "<上の tealus_gate の式>"
    </RequireAny>
</Else>
```

  - `Sec-Fetch-Dest` は偽れるが、偽っても通れない (iframe の枝ではクッキーが必須。偽った相手はベーシック認証の道を失うだけ)。このヘッダを送らない古いブラウザは `Else` に落ちて、今までどおり
  - ap_expr でヘッダを見る書き方は `%{HTTP:Sec-Fetch-Dest}`。`%{HTTP_SEC_FETCH_DEST}` は 500 になる
  - ★ 残る穴: パネルを開いたまま 12 時間を越えると、**画像だけが黙って出なくなる**。開き直せば戻る (割り切る)

### 4.5 鍵は 2 本 (混ぜない)

| 鍵 | 持つ者 | 置き場 |
|---|---|---|
| 通行証の鍵 (HMAC-SHA256、32 バイト以上) | Tealus サーバ / 入口の PHP | Tealus: `~/.tealus/app-pass/<ホスト名>.key` (16 進の 1 行)。相手側: 公開ディレクトリの外 |
| クッキー用の合言葉 | 入口の PHP / `.htaccess` | 相手側だけ。★ Tealus は持たない |

- ★ **部屋に平文で貼らない。** 通行証の鍵は本体班がファイルに作り、portal班が同じマシンからそれを読んで相手側に置く
- 鍵を替えるときは、両方を同時に替える。替えた瞬間に出ていた通行証 (最大 2 分) は通らなくなる。クッキーは合言葉を替えれば全部切れる

## 5. Tealus 側の作り

### 5.1 アプリの設定

`rooms.app_urls[]` の 1 件に `pass: true` を足せる (部屋の管理者が、部屋の設定のアプリパネルで「Tealus の通行証を添える」を付ける)。既定は付けない。

### 5.2 通行証を出す口

`POST /api/rooms/:id/app-pass`  本文 `{ index, url }`

- 部屋の**メンバー**だけ (`requireMember`)。
- `app_urls[index]` が在り、その `url` が本文の `url` と一致し、`pass === true` であること。
  ★ `url` も送らせるのは、開いている間に管理者が並べ替えたとき、別のアプリの通行証を出さないため
- URL は `https:` に限る。ホスト名の鍵ファイルが無ければ出さない (= そのサイトとは取り決めが無い)
- 返すのは `{ url }`: `<アプリの origin>/tealus-gate/?tealus_pass=<通行証>` + アプリの URL のハッシュ。
  通行証の `to` には、アプリの URL のパスと問い合わせを入れる
- ★ 入口の場所 `/tealus-gate/` は、すべての相手で同じ決まりにする (相手ごとに設定を持たない。増えたら考える)
- 出せないときは 404 (どの条件で落ちたかは、外には言い分けない。記録には残す)

### 5.3 画面

- 「通行証を添える」が付いたアプリを開くとき、先に 5.2 を呼び、返った URL を iframe に入れる
- 呼べなかったときは、元の URL をそのまま開く (今と同じくベーシック認証が出る。壊れない)
- 開き直すたび (パネルを閉じて開く・タブを替える) に新しい通行証を取る

### 5.4 ホーム画面のタブ (portal_links) — 2026-10-18 に足した

★ **部屋のアプリだけに付けていて、ホーム画面の「社内ポータル」が相手側の案内ページになった** (改善ループ 8 回目の A)。
ホームのタブは部屋のアプリパネルと別の作り (`HomePage.tsx`) で、URL をそのまま iframe で開いていた。
★ 同じ URL を開く入口は、作りの違う画面まで数えること (#607 の 5 件はアプリパネルだけを数えていた)。

- `portal_links.pass` (既定 false) を足し、管理画面のポータルの管理で付ける
- 口: `POST /api/rooms/portal-links/:id/app-pass`。通す範囲は**タブが見えている人** = ゲストを除くログイン中の人 (`GET /api/rooms/portal-links` と同じ #282)。機械は除く。止めた (`is_active = false`) リンクには出さない
- 通行証の `room` は `"home"` (部屋に結びつかないため)
- 画面は部屋のアプリと同じ扱い (取れるまで about:blank、取れなければ元の URL、開き直すたびに取り直す)。「新タブで開く」は元の URL のまま (パネルの外なのでベーシック認証が出る)

## 6. 決めたこと

### 6.1 クッキーは 12 時間・延長しない (2026-10-18 小野さん)

- 開くたびに延長すると、延長のときに Tealus が関わらないので、**部屋から外した人も使い続ける限り通れ続ける**
- 延長しなければ、Tealus でアプリを開き直すたびにメンバーかどうかを確かめ直す
- ★ **引き換え: 部屋から外した人は、最大 12 時間通れる** (承知のうえ)
- 12 時間を過ぎて画面を放置すると、画像だけ出なくなることがある。開き直せば戻る

### 6.2 表示名を載せる (2026-10-18 小野さん)

- 認証を飛ばすと、相手側の記入者 (`REMOTE_USER` 由来) が空になるため
- ★ 通行証は URL に乗るので、**相手側の Apache の記録に名前が残る** (承知のうえ)

### 6.3 通行証は使い切りにしない

リンクの下見が先に取りに来ても、本人が開けるように。代わりに期限を 2 分と短くする。

## 7. 作らないもの

- **Tealus がアプリの中身を中継すること** — 外のページが Tealus と同じ origin で動くと、そのページの JavaScript から Tealus のログイン情報が読める
- **URL にベーシック認証の ID とパスワードを埋めること** — Chrome は iframe のこの形を止める。パスワードが部屋のメンバー全員に見える
- **クッキーの延長** (§6.1)
- **相手ごとの細かい権限** (部屋の中の誰を通すか) — 通す範囲は部屋のメンバー全体

## 8. 試すこと

- Tealus 側: 通行証の形・署名・期限・`to` / 入口の URL の組み立て (ハッシュを保つ) / 鍵ファイルの読み方 / 口の決まり (メンバーでない・`pass` が無い・`url` が合わない・鍵が無い・`http:`)
- 通しの試し: iPhone の Tealus で、ベーシック認証のアプリを開く → パスワードを聞かれない / 閉じて開き直しても聞かれない / 部屋から外すと、新しい通行証が出ない
