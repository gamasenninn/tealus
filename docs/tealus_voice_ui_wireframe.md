# tealus 音声UI ワイヤーフレーム

## コンセプト
**チャットは止めない、音声は上に重ねる**

- 画面遷移なし
- 下から出るボトムシート
- 音声は即送信
- 文字起こしとAI整形は遅延反映
- 必要なら文字起こしだけ編集可能

---

## 1. 通常状態

```text
┌──────────────────────────────┐
│ トーク履歴                     │
│                                │
│ こんにちは                     │
│ OKです                         │
│                                │
│                                │
├──────────────────────────────┤
│ [＋] [🎤] [メッセージ入力欄      ] [送信] │
└──────────────────────────────┘
```

ポイント:
- 🎤 が音声入力の入口
- テキスト入力と音声入力を並列に置く
- 既存のチャット体験を壊さない

## 7. 編集モード

```text

│ 🎤 音声メッセージ               │
```

## 8. 編集履歴

```text
┌──────────────────────────────┐

│                                │
│ v1: 敵がきた                   │
```

## 設計の要点

### 1. 音声は特別扱いでよい
- テキストは完成品
- 音声は未完成のまま先に送れる
- 後から文字になり、整い、必要なら直せる

### 2. 遅延は弱点ではなく進行中として見せる
- 「待ち」ではなく「成長中のメッセージ」として扱う

### 3. tealusの特徴になる
- まず話す
- あとで整う
- 最後に必要なら人が直す

---

### 4. AI に頼むときは「話す → 拾い直す」の 2 段 (2026-10-24 追加)

音声から AI (アシスタント・@cc-〇〇 の班) に頼むときは、音声の便に宛先を持たせない。
**まず話して送り、整った文字起こしを「エージェントに送る」で入力欄に拾い直し、直して宛先を付けて文字の便で送る。**

- 間に入力欄が挟まるので、聞き間違いを直してから AI に渡せる (AI が誤りのまま動かない)。入力欄は文字起こしの編集画面より広く、じっくり直せる
- 宛先は帯で押すたびに、その場で入力欄の先頭に入る (もう一度押すと消える。複数の班に送ることが多い)。@アシスタント は先頭に置く。
  ★ 最初は「決定」でまとめて入れたが、帯が横に流れて「決定」が右端に行き、探すのが負担だった (同日 案 C に変えた)
- 送った音声の文字起こしは 1 行に畳む (同じ文が 2 回並ぶ違和感を消す)。見分けは「同じ人の返信で、先頭が @アシスタント か @cc-〇〇」。DB は変えない (`client/src/utils/sentToAgent.ts`)
- 送った文字の便は、引用の箱を出さず「🎤 音声から」を 1 行だけ出す (押すと元の音声へ)。自分の音声を自分で引用し同じ文が 2 回見えるため。返信のつながりはデータとして残す
- ★ 検討して採らなかった案: 話す前に宛先を選ぶ / 話し始めに宛先を言う (どちらも直す場面が無い) / 文字だけ返して入力欄に入れる (声の記録が残らない)
- 利用者の言葉: 「まず自分が考えてることを普通にしゃべる。その後このメッセージをどう料理するかは後で。入力段が途中に挟まると、めちゃよい感じ」

## 一言コンセプト案

- **まず話そう。整えるのはあとでいい。**
- **未完成のまま送れるチャット。**
- **書く前に送れるメッセンジャー。**
