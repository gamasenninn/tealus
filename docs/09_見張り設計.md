# 見張り設計 — 来るはずのものが来ないとき、業務メモに 1 回だけ知らせる

★ 2026-10-13 起草 (改善ループ 1 回目の 1 番、利用者が選んだもの)。同日に**汎用の形へ作り直した** (§0)。
★ 姉妹の仕組みは `06_ルームトリガー設計.md`。**作りの多くをそちらから借りている**ので、§3 と §10 を先に読むこと。

## 0. ★ 原則 —— Tealus が見るのは自分の境界まで

最初の版 (同日の午前) は、無線の ptt が自分で決めた JSON の形 (`{"services":{"vox":"up"}}`) を本体が読み、
バックアップも repo の外にある**私たちのスクリプトの記録の形**を読んでいた。**会社の事情が本体の中に漏れていた** (利用者の指摘)。

作り直しの線引き:

| 見るもの | 誰の責任か |
|---|---|
| Tealus の部品 (`tealus-cli` など) が動いているか | **Tealus** —— 部品から鼓動を送ってもらう (§3.2) |
| 機械が投稿する部屋の流れが止まっていないか | **Tealus** —— 部屋は Tealus のもの (§3.3) |
| Tealus のバックアップが成功しているか | **Tealus** —— バックアップのスクリプトを repo に入れ、Tealus の機能にする (§9) |
| ptt の中 (録音・文字起こし) が動いているか | **ptt** —— ptt の配信サーバ (9320) はすでに止まったことを検知している。知らせるなら ptt から Tealus へ投稿する |

★ **ptt と Tealus は `tealus-cli` で仲介されているだけ (疎結合)**。Tealus はその CLI までを見る。
★ 汎用であることの担保は、**何を見るかを設定ファイル (JSON) で定義すること** (§5)。会社固有の値は設定ファイルにだけ書く。

## 1. 何を作るのか

本番には「毎日・毎時に起きるはずのもの」がいくつもある。**それが止まったときに、今は誰にも知らせが来ない** (2026-10-13 調べ)。

| 流れ | 止まったら、今は誰が気づくか |
|---|---|
| 毎朝 3:00 の NAS バックアップ | 人が `npm run doctor` を手で叩いたときだけ |
| 通話履歴の取り込み (SP2TXT) | SP2TXT 自身が「録音取込 停止の疑い」を出すが、**SP2TXT が死ぬとその警告も一緒に死ぬ** |
| 無線の送り込み (`tealus-cli send --watch`) | 誰も。部屋が静かになるだけで、静かな日と見分けが付かない |

作るのは 1 つだけ: **本体が数分ごとに「来ているか」を見て、異常になったら業務メモに 1 回、戻ったら 1 回知らせる。**

## 2. 実測 (2026-10-13 11:5x、直近 30 日・水曜を除く・9:00〜17:00)

部屋への投稿の間隔:

| 部屋 | 間隔の中央 | 95% | 99% | 最長 |
|---|---|---|---|---|
| 通話履歴 (SP2TXT の投稿) | 8.5 分 | 49 分 | 81 分 | **125 分** (10-10 土 17:23〜) |
| トランシーバー履歴 (無線) | 4.4 分 | 32 分 | 57 分 | **250 分** (10-02 金 11:41〜) |

★ **通話履歴は「静かすぎる」で見張れる** (最長 125 分 → 閾値 150 分)。
★★ **無線は投稿の間隔では見張れない。** 静かな日は 4 時間空く。→ 送り込みの CLI から鼓動を送ってもらう (§3.2)。

★ 水曜は定休 (10-07 は全経路が 0〜3 件。SP2TXT のコードにも「水曜定休」がある)。

## 3. 仕組みは 1 つ。見方が 3 種類

共通のループ 1 本 (5 分ごと) が、設定ファイルの各行を見方 (`kind`) に従って判定する。

| `kind` | 何を見るか | 異常 |
|---|---|---|
| `heartbeat` | Tealus の部品が送る鼓動 (§3.2) | 鼓動が `max_silence_minutes` を超えて来ない / 一度も来ていない / 送り込みが遅れている |
| `room_quiet` | 部屋の、指定した送り手の最新の投稿 | 稼働時間の中で `max_quiet_minutes` を超えて投稿が無い |
| `backup_log` | Tealus のバックアップの記録 (`backup-YYYYMMDD.log`、§9) | 最後の記録に「=== 終了: 成功 ===」が無い / 26 時間より古い / 置き場が読めない |

★ `backup_log` の判定は agent-server の doctor にある `judgeBackup` と**同じものを使う** (本体側 `services/backupLog.mts` に置き、doctor はそれを import する)。
  **同じ判定を 2 か所に書かない** —— 片方だけ直して食い違うと、壊れを隠す。

### 3.1 稼働時間 (`room_quiet` だけ)

`room_quiet` は「夜は静か」が正常なので、稼働時間 (`hours`・`days`) の外では**判定しない** (異常にも、戻ったにもしない)。
稼働時間に入ったら、**稼働開始の時刻から**数える (前夜の最後の投稿から数えると、毎朝鳴る)。

### 3.2 鼓動 (`heartbeat`)

Tealus の部品が `POST /api/bot/heartbeat` に `{ name, info }` を送る。本体は**送った人 (ログインした利用者) と名前の組**ごとに最後の時刻を 1 行だけ覚える。

```
tealus-cli send ... --watch <dir> --heartbeat radio-sender
  → 1 分ごとに { name: "radio-sender", info: { latest_file_at, last_sent_at } }
```

★ **プロセスの一覧を外から見る方式は採らない。**
  1. 同じマシンでしか使えない (CLI は API につなぐだけなので、別のマシンでも動かせる)
  2. OS ごとに取り方が違い、本体に OS 依存の部品が入る
  3. **生きているが働いていない**を拾えない (10-12 の #582・#587 はどちらも「プロセスは生きていたが送り方がおかしかった」)

★ `info` に「監視しているフォルダの最新のファイルの時刻」と「最後に送った時刻」を入れると、
  **最新のファイルは新しいのに送っていない** (= 詰まり) も見られる (`max_send_lag_minutes`)。

★★ **鼓動は表に覚える (`heartbeats`)。** 「状態は持たない」(§3.4) の例外。鼓動は投稿ではないので、引ける場所が他に無い。
  1 部品 1 行 (上書き) なので増えない。部品を消したら行も消してよい。
★ 鼓動は**知らせ**ではない。部屋には何も流れない (1 分ごとに投稿すると部屋が埋まる)。

### 3.3 知らせるのは「変わったとき」だけ

```
正常 → 異常   業務メモに「⚠ <名前> が止まっているようです」+ 何を見てそう判断したか
異常 → 異常   何もしない (★ 5 分ごとに鳴らさない)
異常 → 正常   業務メモに「✅ <名前> が戻りました (約 N 分止まっていました)」
```

★ **「落ちた」を知らせるなら「戻った」も対で知らせる。** 戻ったことが分からないと、人が確かめに行く手間が残る
(cc-stream の `recovered` と同じ理由、`listen-tealus` SKILL.md)。

### 3.4 知らせの状態は持たない —— 業務メモの自分の投稿から引く

ルームトリガーと同じ作法 (06 §3.1.1)。「前回は異常と知らせたか」は、業務メモで印 (§5) の付いた自分の最新の投稿が ⚠ か ✅ かで決める。

- 本体を再起動しても、異常の最中なら**もう一度は鳴らない** (前の ⚠ が残っているから)
- 初めて動かしたときは「前回は正常」とみなす (印の付いた投稿が無い)

### 3.5 判定に失敗したら

DB に届かない・設定が壊れている、は**見張り自身の不具合**なのでログ (warn) に出し、業務メモには出さない。
★ 1 行の失敗が他の行を止めないよう、行ごとに囲う (ルームトリガーの `runOnce` と同じ)。

### 3.6 4 つ目の見方 `push_reach` —— 通知が届かない人 (2026-10-16 追加)

改善ループ 7 回目の 1 番 (利用者が選んだもの)。

**何が起きていたか**: プッシュの宛先 (購読) が 1 本も無い人には、通知が 1 件も届かない。
それを本人も管理者も知らない (`services/push.mts` は宛先が 0 なら黙って戻る)。
10-16 の実測: 有効な利用者のうち 4 人が宛先 0 本。1 人は 10-13 に iPhone の宛先が Apple 側で無効になり、以後 184 件が素通り。
★ 送信の失敗率 (14 日で 1%) を見ても見つからない —— **送っていないものは失敗として数えられない**。

**これは Tealus の境界の中** (§0): 宛先も通知も Tealus のもの。

**作り**: 1 行の設定が**人ごとの見張り**に開く。印は `— 見張り (watchdogs: <id>:<user_id>)`。
状態は人ごとに業務メモの自分の投稿から引くので、§3.3 の「変わったときだけ」がそのまま人ごとに効く
(A さんが ⚠ のままでも、あとから B さんが 0 本になれば B さんの ⚠ が 1 回出る)。

| 人の状態 | 判定 |
|---|---|
| 有効な宛先が 1 本以上 | 正常 |
| 有効な宛先が 0 本 | 異常 (最後の宛先が無効になった時刻、または「一度も登録が無い」を添える) |
| 直近 `active_within_days` 日 (既定 30) に何も読んでいない | **判定しない** (状態を変えない) |

- 対象は、有効で機械でない利用者のうち、部屋に 1 つ以上入っている人。`exclude_user_ids` は外す (試験用のアカウントなど)
- ★ **「最近使っている」は既読の記録 (`room_read_cursors.last_read_at`) で見る。** `users.last_seen_at` はどこからも更新されておらず全員空 (10-16 確認)
- ★ 使っていない人を外すのは、知らせても本人が見ないから。使い始めた日 (= 読んだ日) から判定に入る
- 知らせの本文に直し方を書く: 本人の端末で Tealus を開き、プロフィールの「この端末で通知を受け取る」を押す (#546。iPhone はタップしないと登録し直せない)
- ★ 関連 (同じ日の 3 番): 本体は **30 日送り直されない宛先を外す** (`push.mts` の `deactivateStaleSubscriptions`、`PUSH_STALE_DAYS`)。画面はログイン・起動・**表に出たとき** (6 時間に 1 回まで) に送り直すので、使っている端末は外れない。外れても開き直せば戻る。
  ★ 7 日にしなかったのは、表に出たときの送り直しを入れる前の実測で、毎日使っている 4 人の唯一の宛先が 7 日より古かったため。この掃除で最後の 1 本が外れた人は、上の `push_reach` が知らせる

## 4. 置き場 —— 本体に置く

| 置き場 | 止まったとき |
|---|---|
| **本体 (採用)** | 見張りも止まる。ただし本体が止まると**画面もプッシュも止まる**ので、利用者がすぐ気づく |
| agent-server | agent-server が止まると見張りが黙る。agent-server 自身は誰も見張っていない |

★ **見張りが見張られる側と一緒に死なないこと**が要点。本体の死は見張りの範囲外 (§7)。

## 5. 設定ファイル

ルームトリガーと同じ作法 —— 判定のたびに読み直す (再起動不要)、`.example.json` を repo に置き実ファイルは gitignore。

```
server/config/watchdogs.json          実ファイル (gitignore)
server/config/watchdogs.example.json  repo に置く見本
```

```json
{
  "notify": { "room_id": "<業務メモ>", "room": "業務メモ", "as_user_id": "<投稿する人>" },
  "watches": [
    { "id": "backup", "name": "NAS へのバックアップ", "kind": "backup_log",
      "dir": "//hksagri/ymain/tealus-bak/logs", "enabled": true },
    { "id": "call-log", "name": "通話履歴の取り込み (SP2TXT)", "kind": "room_quiet",
      "room_id": "<通話履歴>", "room": "通話履歴", "from_user_ids": ["<SP2TXT の投稿者>"],
      "max_quiet_minutes": 150, "hours": "09:00-17:00", "days": "mon,tue,thu,fri,sat,sun", "enabled": true },
    { "id": "radio-sender", "name": "無線の送り込み (tealus-cli)", "kind": "heartbeat",
      "heartbeat": "radio-sender", "from_user_id": "<CLI がログインする利用者>",
      "max_silence_minutes": 10, "max_send_lag_minutes": 15, "enabled": true }
  ]
}
```

★ バックアップの置き場はネットワークの名前 (`//hksagri/...`) で書く。`S:` はログオンした人の画面にだけ見える割り当てで、
  本体を別の起動のしかた (タスクなど) で動かすと読めなくなる。名前で書けば起動のしかたに依存しない。
★ **投稿者は Claude (本体班) にする。プッシュは鳴らさない** (2026-10-13 利用者判断)。
  Claude は機械 (`is_bot`) の扱いで、業務メモは機械の投稿を鳴らさない設定 (`push_machine_posts=false`、#463)。
  止まる頻度は低いので、まず業務メモを開いたときに気づく形で様子を見る。鳴らす必要が出たら、メンションか部屋の設定で足す。
★ 投稿の 2 行目に印 `— 見張り (watchdogs: <id>)` を置く (06 §10 と同じ理由。`room-triggers:` と別の語にして、トリガーの「前回撃った時刻」の検索に混ざらないようにする)。
★ `id` は印に埋まる = **変えると前回の状態が切れる** (06 §4.0 と同じ)。

## 6. 作らないもの

- **直すこと (再起動など)。** 見張りは知らせるだけ。直すのは人 (止まった原因を見ないまま立ち上げ直すと、壊れを隠す)
- **Tealus の外のプログラムの中身を読むこと。** ptt の `/api/health` のような、相手が決めた形を本体が知らない (§0)
- **プロセスの一覧を見ること** (§3.2)
- **「正常です」の定期報告。** 毎日鳴る口は読まれなくなる (doctor の約束 3)
- **閾値の自動学習。** 閾値は §2 の実測から人が決めて設定ファイルに書く
- **業務メモ以外への知らせ** (メール・LINE など)
- **本体自身の死活。** 自分が死んだことは自分では言えない。外の目が要る (§7)

## 7. 受け入れる穴 (名前を付けておく)

- **ptt の中 (録音・文字起こし) が止まっても、送り込みの CLI が生きていれば気づかない。** ptt の責任 (§0)。
  ptt の配信サーバ (9320) は止まったことを検知しているので、そこから Tealus に投稿するのが筋 (ptt 側の判断)
- **稼働時間の外で止まったもの**は、翌日の稼働開始から `max_quiet_minutes` 後に気づく
- **祝日**は `room_quiet` が誤って鳴りうる (⚠ と ✅ の 2 回で済む)。祝日の暦は持たない
- **本体が止まっている間**は何も見ていない (§4)
- **本体を再起動した直後**、鼓動の表は残っているので問題ない。ただし本体が長く止まっていた場合は、
  戻った直後に「鼓動が来ない」と判定しうる (CLI は本体が止まっている間は送れない)。起動直後は 1 回目の判定を遅らせる (`FIRST_RUN_MS`)

## 9. バックアップを Tealus の機能にする

`backup_log` が見る記録の形 (`backup-YYYYMMDD.log` と「=== 終了: 成功 ===」) は、**repo の外にあった私たちのスクリプトの形**だった。
→ スクリプトを `scripts/backup/tealus-backup.ps1` として repo に入れ、記録の形を**Tealus の約束**にする。

- 置き先・コンテナ名・repo の場所は**引数**にする (会社の値は呼ぶ側に書く)
- 本番のタスクは今の場所 (`~/.tealus/backup/tealus-backup.ps1`) を呼んだまま。そのファイルを **repo 版を引数つきで呼ぶだけの殻**にする
  (タスクの設定を変えるには管理者の権限が要るため、触らずに済む形にした)
- ★ 鍵と設定の写しに `server/config/watchdogs.json` を足す (gitignore で外している会社の設定なので、他と同じく失うと作り直しになる)
- 受け入れる穴: **Windows (PowerShell 5.1) 版だけ**。Linux で動かす採用者向けの版は無い (要る採用者が出たら作る)
