# 通話履歴の修正候補を出す

## 何をするか / しないか

```
する    ★ 誤変換らしき箇所を挙げ、直した形と根拠を出す
しない  ★★ 本文を編集する            ← 評価が済むまで禁止 (#381 の教訓: 測る前に入れない)
しない  ★★★ 音声に無い情報を埋める    ← 下の「禁止事項」参照
```

**出力は候補ファイルだけ。** ルームの投稿も編集もしない。

## 入力

- ルーム `通話履歴` (`5ddd2179-…` ではない。ID は実行時に `list_rooms` で引く)
- 投稿者は `通話履歴ボット` (SP2TXT)。書式は `【通話】sum_NNNNN / 日時 【カテゴリ】… 【顧客名】… 【商品名】…` + 本文
- ★ **SP2TXT は投稿前にすでに LLM 補正を 1 回かけている** (2026-08-15 以降、`organon.ttl` を知識源にした `_tls` 版)。
  ここで見るのは**その残差**であって、素の文字起こしではない。

## 知識源

```
C:\app\tealus-organon\tools\organon.ttl   ★ 公開契約 (射影前の raw グラフ)。人名・社名・alias・型
Tealus の辞書テーブル                       dictionary_terms / dictionary_aliases (source=organon/auto/manual)
同じルームの過去便                          同じ顧客・同じ商品が繰り返し出る。前後の便が最良の文脈
```

★ **`organon.ttl` の `org1:alias` は「その語がどう聞こえるか」の一覧**で、**型 (`Role` / `Organization`) と `vendorClass` が付いている**。
「音が似ている」だけで直さず、**その語がその文脈に居てよい型かを見る** (客先の名前が整備担当の位置に出てきたら疑う)。

## ★ 禁止事項 (能力の限界ではなく、規則として守る)

1. **「不明」を埋めない。** `【顧客名】不明` → 具体名は、音声に情報が無く人が知識で補っている。
   埋めると**間違った相手の名前が通話記録に残る**。
2. **音声に無い固有名詞を足さない。** 空欄への追記 (`'' → '宮城県'`) は人の補完。候補に出さない。
3. **迷ったら触らない。** 過剰修正は 1 件でも「人が全文を読み直す」に直結し、**手間が減らずに増える**。
4. **要約そのものを書き直さない。** 文の作り直し (`飛行船ファームです → うみさわむ`) は再構成であって修正ではない。

## 修正のクラスと方針

2026-08-27 に、人 (小野さん) の実際の編集 493 か所を分類した結果:

| クラス | 割合 | 例 | 方針 |
|---|---|---|---|
| ① 整形の削除 | 23% | `【佐藤】` `おはようございます。` 行頭の `-` | ★ 規則で処理。LLM の判断を使わない |
| ② 空欄への追記 | 6% | `'' → '吉原造園'` | ★ 禁止 (上記 2) |
| ③ 不明 → 具体名 | 2% | `不明 → 阿部` | ★ 禁止 (上記 1) |
| ④ 辞書に載っている語への置換 | 11% | `飛河区 → ヒカカク` `遺跡 → イセキ` | 候補に出す。**根拠に辞書の行を添える** |
| ⑤ 短い置換 (辞書外) | 52% | `車 → 会社` `農 → 乗` `安 → 靖` `T → 2` | ★ **本命かつ最も危ない**。文脈の根拠を必ず書く |
| ⑥ 大きな書き換え | 3% | `立ちウォーター → 常陸太田` | 原則 触らない (④ で説明できる場合のみ) |

★ **① で分かっている規則** (人が毎回消しているもの):

```
【人名】形式の話者ラベル      行中どこでも削除
行頭の "-" だけの行           削除
定型のあいさつ                「おはようございます。」等が単独で残っている場合
```

★ **社内の呼称ルール** (誤変換ではないが人が必ず直す):

```
ファーム → アグリ    ★ 「飛行船ファーム」は旧称。現在は「飛行船アグリ」
```

## 出力

**2 か所に出す。**

1. **通話履歴ルーム (`f3ee3f54-e7f2-424d-b481-5b0028921026`) に 1 日 1 便、`send_form` で。**

```
1 候補 = radio 1 問。label に 「誤 → 正 (sum_NNNNN 根拠を一言)」
選択肢  「直してよい」/「★ 直すな」(allow_text で理由欄) /「保留」
required: false          ← ★ 未回答＝保留。全部埋めさせない (1 日 40 問は続かない)
reply_mention "@cc-tealus"  ← 回答がこちらを起こすので × を自動で記録できる
1 便 10 問まで            ← 実測 30 通で 36 候補。溢れた分は翌日に回す
```

★ **`required` を付けない / 「○ を押してください」と書かない。** 押すのは気になったものだけ、を維持する。
★ **organon の Q0 と同じ便に混ぜない。** 道具は同じ (`send_form`) だが、1 回の回答が 2 つの目的に使われる形にしない。
   ★ **小野さんに求めるのは「これは直すな」の番号だけ。** ○ は求めない (無反応＝保留)。
   理由: 編集履歴からは「直した箇所」しか取れず、**「直してはいけない箇所」のデータが存在しない**。
   × だけがそれを作れる。2026-08-27 の n=30 測定で、この不足のため合否判定ができなかった。
2. `report/call-log-fix/YYYY-MM-DD.jsonl` に 1 行 1 候補で書く (`report/` は gitignore 済)。

```json
{"message_id":"…","class":"⑤","before":"農","after":"乗","context":"…前後 20 字…","reason":"文脈は乗用草刈機の話。organon に『農』の語なし","confidence":"high|low"}
```

- **`reason` は必須。** 「辞書にあるから」だけでは ④ でも不足で、**どの entry か**まで書く。
- ★ **`confidence` を足切りに使わない。** 2026-08-27 の n=30 で **high 18 件中 7 件が外れ / low 18 件中 10 件が当たり**。
  自己申告の確信度は当たり外れをほとんど分けなかった。**絞るなら「辞書に載っているか」等の外形で絞る。**

## 落とし穴

- **二重補正**: SP2TXT `_tls` が投稿前に補正済み。ここで直す分は残差なので、**SP2TXT 側を触ると評価の前提が変わる**。
- **辞書は関係を持たない**: `dictionary_aliases` は射影後の平坦な並び。**型や所属を使うなら `organon.ttl` を読む**。
- ★ **短い alias は無関係語を壊す**: 1099 alias 中 261 件が 2 文字。`カット→加藤` `サイト→齋藤` の盲目置換は
  2026-07-06 に実データで精度ほぼ 0% と測定済み。**文脈を読まずに alias を当てはめない。**
