# 通話履歴の誤変換を直す

## 何をするか / しないか

```
する    ★ 誤変換らしき箇所を挙げ、直した形と根拠を出す
する    ★★ 根拠が「その場」にあるものは 本文を編集する   ← 2026-08-28 解禁 (下記)
しない  ★★★ 根拠が自分の一般知識しか無いものを編集する   ← 候補どまりにする (下記)
しない  ★★★ 音声に無い情報を埋める                      ← 下の「禁止事項」参照
しない  ★★★ 要約そのものを書き直す                      ← 語の置換までにする
```

### ★ 本文編集は 2026-08-28 に解禁された

`#381` の教訓 (測る前に入れない) を踏まえ、**1 日 候補だけ出して評価してから**投入した。

```
2026-08-27  候補 10 件を提示 → 小野さん 10/10「直してよい」、戻し 0
2026-08-28  user 判断で本文編集へ。36 便 / 21 便を編集 / 72 か所
            確認 20 問 → 戻し 0 / 保留 1 / 未回答 1
```

**編集は `message_edits` に残るので必ず戻せる。** これが解禁の前提。

### ★★ 編集してよいもの / 候補どまりにするもの

```
編集してよい   同じ通話の別の箇所 / 要約 / 辞書 / 前日以前の同一顧客の便
★ 候補どまり   自分の一般知識だけが根拠 (車種の純正タイヤサイズ、型番の対応、地理 など)
```

**候補を作ったら「この根拠は本文 / 辞書 / 前便のどれで示せるか」を自問する。どれでも示せないなら編集しない。**

★ 根拠: 2026-08-28 の 20 問で、**「直したままでよい」以外は 1 件だけ**で、
**その 1 件だけ根拠の性質が違った**。

```
19 件  その場に証拠がある                        → すべて ok
1 件   「235/65R18 は プラド の純正サイズ」だから  → ★ 保留 (ブラノ → プラド、sum_84287)
```

**その通話を読んでも確かめようがないので、人は判断できない。判断を求めること自体が負担になる。**

### 編集の手順

`edit_message` の**局所置換モード**を使う (全文差し替えは使わない)。

```
1. ローカルで出現数を数える            ← before 文字列が想定どおりか
2. edit_message(before, after, expected_count)   ← 件数が違えば置換しない
3. ★ 適用後に get_messages で取り直し、実状態で検算   ← 独立した 2 本目の経路
```

★ **自分の数え上げだけで済ませない。** `expected_count` はサーバ側のガードで、
取り直しは**書けたことの確認**。片方だけだと「自分の想定を自分で検算する」形になる。

## 入力

- ルーム `通話履歴` (`5ddd2179-…` ではない。ID は実行時に `list_rooms` で引く)
- 投稿者は `通話履歴ボット` (SP2TXT)。書式は `【通話】sum_NNNNN / 日時 【カテゴリ】… 【顧客名】… 【商品名】…` + 本文
- ★ **SP2TXT は投稿前にすでに LLM 補正を 1 回かけている** (2026-08-15 以降、`organon.ttl` を知識源にした `_tls` 版)。
  ここで見るのは**その残差**であって、素の文字起こしではない。

## 知識源

### ★★ 辞書は 3 層ある。どれを見たかを必ず言えるようにする

```
canon      C:\app\tealus-organon\tools\organon.ttl        organon班が管理。alias を全部持つ
射影       projectOrganonDict(canon) → 234 terms/552 alias  #381 で恒等・敬称重複を畳む
★ テーブル  server/config/dictionary.local.ttl → 283 terms   organon 由来 + auto/manual/base (~49 語)
```

★ **「辞書に在るか」を答えるなら見るのはテーブル。** 射影は organon 由来の部分集合にすぎない。
`dictionary.local.ttl` は本体がテーブルから書き出す写しなので **DB 直 query 無しで読める**。

★ **canon の alias 数と辞書の alias 数は一致しない** (#381 が恒等・敬称つきを畳むため)。
`木尾野` は届くが `木尾野さん` は届かない、という形になる。

★ 2026-08-28 に、**射影だけを見て「テーブルにも無い」と断定して外した**。
`北店` の alias `2点` はテーブルにしか無かった。**見ていない層について「無い」と言わない。**

```
同じルームの過去便   同じ顧客・同じ商品が繰り返し出る。前後の便が最良の文脈
```

★ **`org1:alias` は「その語がどう聞こえるか」の一覧**で、**型 (`Role` / `Organization`) と `vendorClass` が付いている**。
「音が似ている」だけで直さず、**その語がその文脈に居てよい型かを見る** (客先の名前が整備担当の位置に出てきたら疑う)。

### ★ 辞書に在っても適用されるとは限らない (両方向に外れる)

補正段は**テーブル全件を截り無しで prompt に載せる** (283 中 271、`term` 12 件のみ除外)。
順位付けも上限も無い。**「なぜこの語が選ばれたか」という問いは成立しない。**

そのうえで 2026-08-28 に**両方向の外れ**が同日に出た:

```
適用されすぎ   2点 → 北店      (真値は 第二展示場。第二展示場 は shared-kernel で射影対象外 = 出せない)
適用されなさすぎ 強烈 → 共立    (辞書に別名として在ったのに補正段は直さなかった。sum_84299)
```

★ **辞書に在ることは、直る保証でも 誤爆の証明でもない。** 候補の根拠に使うのはよいが、
「辞書に在るから直っているはず」とも「辞書に在るから誤爆したはず」とも書かない。

## ★ 禁止事項 (能力の限界ではなく、規則として守る)

1. **「不明」を埋めない。** `【顧客名】不明` → 具体名は、音声に情報が無く人が知識で補っている。
   埋めると**間違った相手の名前が通話記録に残る**。
2. **音声に無い固有名詞を足さない。** 空欄への追記 (`'' → '宮城県'`) は人の補完。候補に出さない。
3. **迷ったら触らない。** 過剰修正は 1 件でも「人が全文を読み直す」に直結し、**手間が減らずに増える**。
4. **要約そのものを書き直さない。** 文の作り直し (`飛行船ファームです → うみさわむ`) は再構成であって修正ではない。

## 修正のクラスと方針

2026-08-27 に、人 (小野さん) の実際の編集 493 か所を分類した結果:

| クラス | 割合 | 例 | 方針 |
|---|---|---|---|
| ① 整形の削除 | 23% | `【佐藤】` `おはようございます。` 行頭の `-` | ★ 規則で処理。LLM の判断を使わない |
| ② 空欄への追記 | 6% | `'' → '吉原造園'` | ★ 禁止 (上記 2) |
| ③ 不明 → 具体名 | 2% | `不明 → 阿部` | ★ 禁止 (上記 1) |
| ④ 辞書に載っている語への置換 | 11% | `飛河区 → ヒカカク` `遺跡 → イセキ` | 候補に出す。**根拠に辞書の行を添える** |
| ⑤ 短い置換 (辞書外) | 52% | `車 → 会社` `農 → 乗` `安 → 靖` `T → 2` | ★ **本命かつ最も危ない**。文脈の根拠を必ず書く |
| ⑥ 大きな書き換え | 3% | `立ちウォーター → 常陸太田` | 原則 触らない (④ で説明できる場合のみ) |

★ **① で分かっている規則** (人が毎回消しているもの):

```
【人名】形式の話者ラベル      行中どこでも削除
行頭の "-" だけの行           削除
定型のあいさつ                「おはようございます。」等が単独で残っている場合
```

★ **社内の呼称ルール** (誤変換ではないが人が必ず直す):

```
ファーム → アグリ    ★ 「飛行船ファーム」は旧称。現在は「飛行船アグリ」
```

## 出力

**3 か所に出す。**

★ **起動は 1 日 2 回。room-trigger が `@cc-tealus` 宛に投稿する** (`server/config/room-triggers.json`)。

```
13:00  tsuwa-fix-candidates      午前分
17:00  tsuwa-fix-candidates-pm   ★ 13:00 以降の分 (13:00 便で出した分は除く)
```

★ **17:00 便がある理由**: 13:00 だけだと**午後の通話が毎日まるごと翌日回し**になる。
2026-08-28 に実証 — **13:00 便は「新規 0 件」→ その後 15 便 (13:26〜16:58)**。
17:00 にしたのは実測 (小野さんの編集は 12時台 53 / 13時台 33 / **17時台 37** 件) で
**人が既に手を動かしている時間に AI が先に出し、そのあと人がリライトする**ため。

1. **直したものの一覧をルーム (`f3ee3f54-e7f2-424d-b481-5b0028921026`) にテキストで投稿。**
   sum / 誤 → 正 / 箇所数 / 根拠 の表。**直さずに残したものも書く** (何を見送ったかが分かるように)。

2. **同じルームに `send_form` で「戻すものだけ」を聞く。**

```
1 候補 = radio 1 問。label に 「誤 → 正 (sum_NNNNN 根拠を一言)」
選択肢  「直したままでよい」/「★ 戻して」(allow_text で理由欄) /「保留」
required: false          ← ★ 未回答＝そのまま。全部埋めさせない (1 日 40 問は続かない)
reply_mention "@cc-tealus"  ← 回答がこちらを起こすので × を自動で記録できる
1 便 10 問まで            ← 実測 30 通で 36 候補。溢れた分は翌日に回す
末尾に自由記述 1 問        ← 10 枠に載らなかったものの受け皿
```

★ **「保留」は戻し指示ではない。据え置いて記録する。勝手に戻さない。**

★ **`required` を付けない / 「○ を押してください」と書かない。** 押すのは気になったものだけ、を維持する。
★ **organon の Q0 と同じ便に混ぜない。** 道具は同じ (`send_form`) だが、1 回の回答が 2 つの目的に使われる形にしない。
   ★ **小野さんに求めるのは「これは直すな」の番号だけ。** ○ は求めない (無反応＝保留)。
   理由: 編集履歴からは「直した箇所」しか取れず、**「直してはいけない箇所」のデータが存在しない**。
   × だけがそれを作れる。2026-08-27 の n=30 測定で、この不足のため合否判定ができなかった。
3. `report/call-log-fix/` に台帳を書く (`report/` は gitignore 済)。

```
YYYY-MM-DD.jsonl              候補 (low 含む全部)
YYYY-MM-DD-applied.jsonl      適用した置換 (before/after/箇所数/applied_at)
YYYY-MM-DD-pm-applied.jsonl   午後便の分
YYYY-MM-DD-verdicts.jsonl     フォームの回答 (ok / revert / hold / unanswered)
```

候補ファイルは 1 行 1 候補で書く。

```json
{"message_id":"…","class":"⑤","before":"農","after":"乗","context":"…前後 20 字…","reason":"文脈は乗用草刈機の話。organon に『農』の語なし","confidence":"high|low"}
```

- **`reason` は必須。** 「辞書にあるから」だけでは ④ でも不足で、**どの entry か**まで書く。
- ★ **`confidence` を足切りに使わない。** 2026-08-27 の n=30 で **high 18 件中 7 件が外れ / low 18 件中 10 件が当たり**。
  自己申告の確信度は当たり外れをほとんど分けなかった。**絞るなら「辞書に載っているか」等の外形で絞る。**

## 落とし穴

- **二重補正**: SP2TXT `_tls` が投稿前に補正済み。ここで直す分は残差なので、**SP2TXT 側を触ると評価の前提が変わる**。
- **辞書は関係を持たない**: `dictionary_aliases` は射影後の平坦な並び。**型や所属を使うなら `organon.ttl` を読む**。
- ★ **短い alias は無関係語を壊す**: 1099 alias 中 261 件が 2 文字。`カット→加藤` `サイト→齋藤` の盲目置換は
  2026-07-06 に実データで精度ほぼ 0% と測定済み。**文脈を読まずに alias を当てはめない。**
  ★★ **ただしこの数字を今の設計に転用しない。** 測ったのは**決定論的な前段置換**で、
  今は **LLM に「転写ブレ例」として文脈つきで渡している**。別の機構なので、
  **「短い alias は危ないか」ではなく「LLM に文脈つきで渡したときも危ないか」を測り直す必要がある。**
  (2026-08-28 に自分がこの転用をやって、根拠として 2 回引用してしまった)
  ★ `サイト → 齋藤` は organon 側にも記録があり (Day 32 / 2026-06-17 に誤確認として撤回)、
  **互いを参照していない 2 本が同じ語で一致した**。元は小野さんの「裸の 2 文字は危ない」という判断。

### ★ 二重補正で要約が壊れる (語だけ直しても直らない)

要約段が**誤読の上に文を組み立てている**場合、語を置換すると要約側が噛み合わなくなる。

```
2026-08-28 sum_84276   豆粉 → 動噴 (13 か所)
  結果  【商品名】噴霧器（動噴用）        ← 動噴＝噴霧器 なので重複
        「動噴散布用の噴霧器を購入したい」  ← 動噴は撒く物ではなく機械
```

★ **要約の書き直しは禁止 (禁止事項 4)。** 語だけ直して、**噛み合わなくなった箇所をルームに明示する**。
**語の置換だけでは要約層は直らない**ことを、直した本人が言う。

### ★ 異種文字の混入 (判断の要らない種類)

```
2026-08-28  自动刈り深さ        簡体字「动」が混入        (sum_84278)
2026-08-28  アルミの मूल्य での査定  デーヴァナーガリー文字   (sum_84287)
```

**1 日で 2 件出た。** 日本語以外の文字が紛れる形は**文字化けであって判断が要らない**ので、
フォームの 10 枠を消費させない方向で小野さんに確認済み (**回答待ち** — 出たら反映する)。
